# Runtime Configuration Inventory

This is the single inventory for environment variables read by the app server,
client bundle, plain Node scripts, Prisma tooling, and E2E tooling. Source code,
tests, and schemas remain authoritative.

`NEXT_PUBLIC_*` values are statically inlined by Next.js into browser bundles at
build time. The helpers in `src/lib/client-config.ts` intentionally keep literal
`process.env.NEXT_PUBLIC_*` reads; do not replace them with computed keys or a
generic accessor. Server-only env access stays in `src/lib/env.ts` and the owned
runtime config modules listed below.

## Trusted proxy client-IP extraction

IP-keyed abuse budgets use a conservative trust policy. In production,
forwarded headers are ignored unless `TRUSTED_PROXY_CIDRS` lists the immediate
reverse proxies allowed to set them and the app can read the peer address
directly or through `TRUSTED_PROXY_REMOTE_ADDR_HEADER`. If that trust boundary is
missing, public/import/anonymous-generation limits use the platform remote
address when available; otherwise they share the `unknown` bucket so spoofed
`x-forwarded-for` values cannot dilute budgets.

Only configure `TRUSTED_PROXY_REMOTE_ADDR_HEADER` for a header overwritten by the
deployment proxy/platform after stripping client-supplied copies. Local and test
environments trust loopback proxy CIDRs by default; production has no implicit
proxy trust.
